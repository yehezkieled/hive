# Sprint 2026-Q2-S7

**Status:** Active
**Window:** 2026-06-16 → 2026-06-30
**Goal:** Open Phase 3 **Track 2** — give Team Leads a reusable, *named*
vocabulary for structuring Workflow fan-outs. S5/S6 proved the Lead→Workflow
engine and hardened the maestro loop, but a Lead still authors every fan-out's
coordination shape from scratch (free-form, no template). S7 establishes **how**
an interaction pattern is delivered to a Lead and ships **one** reference pattern
(`debate`) end-to-end on that mechanism — proving the shape before
blackboard / tournament replicate it in S8 (ahead of the 2026-07-11 Phase 3
deadline). In parallel, on independent surfaces, S7 closes two loop-correctness
gaps: **032** (validate entity/team names before they reach git/worktree paths)
and **033** (tell the PA Maestro it *is* the PA — its prompt never states the
structural role that 024's write-policy already enforces).

## Committed

- [`034-interaction-pattern-library`](../tickets/034-interaction-pattern-library/)
  — Track 2 foundation: fix the pattern-**delivery mechanism** (ADR) and ship the
  `debate` reference pattern end-to-end on it, invokable by a Lead. Mechanism +
  one real consumer in one ticket — a delivery mechanism with no pattern flowing
  through it can't be validated. **Design-heavy / ADR-worthy → full design grill
  in Phase B; the natural spill candidate to S8.**
- [`032-entity-name-validation`](../tickets/032-entity-name-validation/)
  — reject names unsafe for a filesystem path / git ref at every creation path
  (maestro spawn, `/team create`, `spawn_team`), before any worktree or branch is
  made. Carry-forward from 030; fully independent.
- [`033-pa-maestro-self-identity`](../tickets/033-pa-maestro-self-identity/)
  — a maestro's prompt states PA vs. project-maestro (keyed on `is_pa`), so the
  PA stops mis-identifying as a project owner. Found by the S7-planning live
  check; near-independent.

## Risks

- **034 is greenfield + design-heavy.** The delivery-mechanism decision is the
  ticket's pivot and ADR-worthy; if its design grill balloons, **034 spills →
  S8** (as 019 spilled S6→). Its spill is expected, not a miss — S8 is the Phase
  3 finisher with buffer before the 07-11 deadline.
- **033 changes live PA behaviour** → needs a deployed re-smoke (otter
  re-introduces itself as the PA), not just green units.
- **033 / 034 prompt-/JD-seam proximity.** 033 edits prompt assembly +
  `role-maestro.md`; 034 edits skill curation + `role-lead.md`. Overlap is
  minimal, but if both touch role files, rebase the later PR.
- **032 is the clean independent lane** — no collision with Track 2; grab any
  time.

## Out of scope

- **blackboard / tournament / research-consolidate** patterns — **S8**, once 034
  proves the mechanism.
- Mid-run Workflow **steering** (runs stay read-only, ADR 0014).
- Non-Claude leaf models (needs the Phase 5 adapter layer).
- Centralising every scattered PA reference (033 is identity-in-prompt only, not
  a PA-representation refactor).

## Definition of done

- **034:** an ADR fixes the pattern-delivery mechanism; the `debate` pattern
  ships end-to-end on it, invokable by a Lead, documented in `CONTEXT.md` +
  `role-lead.md`, with tests — **or** 034 carries to S8 with the ADR landed.
- **032:** invalid names rejected at all creation paths with a clear, actionable
  error **before** any worktree/branch is made; existing valid names (`otter`,
  `dev`, `hive_dev`, `<maestro>.<team>`) unchanged; boundary cases (`/`, space,
  `..`, leading `-`, empty, shell-meta) tested.
- **033:** a maestro's prompt states PA vs. project-maestro; a deployed re-smoke
  shows otter introducing itself as the PA (owns no project, read-any/
  write-ownerless); project maestros unaffected; PA-vs-project prompt assembly
  tested.
- `ruff` + full `pytest -m "not integration"` green; INDEX rows for 032–034
  reflect final state; `CHANGELOG.md` + the `CLAUDE.md` sprint pointer updated.
