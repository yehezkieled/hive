# Sprint 2026-Q2-S7

**Status:** Active
**Window:** 2026-06-16 → 2026-06-30
**Goal:** Finish Phase 3 by shipping **Track 2** — the named interaction-pattern
library that gives Team Leads a reusable vocabulary for structuring Workflow
fan-outs. S5/S6 proved the Lead→Workflow engine and hardened the maestro loop,
but a Lead still authors every fan-out's coordination shape from scratch
(free-form, no template). S7 fixes **how** a pattern is delivered to a Lead
(034, ADR) and ships all three named patterns on it — **`debate`** (034),
**`blackboard`** (035), **`tournament`** (036) — completing Phase 3. In
parallel, on independent surfaces, S7 closes two loop-correctness gaps: **032**
(validate entity/team names before they reach git/worktree paths) and **033**
(tell the PA Maestro it *is* the PA — its prompt never states the structural role
024's write-policy already enforces). The web/PWA "iPad daily driver" (Phase 4)
follows in **S8**.

## Committed

- [`034-interaction-pattern-library`](../tickets/034-interaction-pattern-library/)
  — Track 2 foundation: fix the pattern-**delivery mechanism** (ADR) and ship the
  `debate` reference pattern end-to-end on it, invokable by a Lead. A mechanism
  with no pattern flowing through it can't be validated, so mechanism + first
  pattern are one ticket. **Design-heavy / ADR-worthy → full design grill in
  Phase B; the spill candidate.**
- [`035-interaction-pattern-blackboard`](../tickets/035-interaction-pattern-blackboard/)
  — the `blackboard` pattern on 034's mechanism: leaf agents read/write a shared
  evolving artifact so each builds on the others' partials. **Blocked by 034.**
- [`036-interaction-pattern-tournament`](../tickets/036-interaction-pattern-tournament/)
  — the `tournament` pattern on 034's mechanism: competing candidates pruned/
  ranked in rounds to a winner. **Blocked by 034.** With 035, completes the named
  library → **Phase 3 done**.
- [`032-entity-name-validation`](../tickets/032-entity-name-validation/)
  — reject names unsafe for a filesystem path / git ref at every creation path
  (maestro spawn, `/team create`, `spawn_team`), before any worktree or branch is
  made. Carry-forward from 030; fully independent.
- [`033-pa-maestro-self-identity`](../tickets/033-pa-maestro-self-identity/)
  — a maestro's prompt states PA vs. project-maestro (keyed on `is_pa`), so the
  PA stops mis-identifying as a project owner. Found by the S7-planning live
  check; near-independent.

## Risks

- **034 is greenfield + design-heavy.** The delivery-mechanism decision is the
  ticket's pivot and ADR-worthy; if its design grill balloons, **034 and its
  dependents 035/036 spill → S8** (as 019 spilled S6→). The 07-11 Phase 3
  deadline leaves S8 buffer.
- **033 changes live PA behaviour** → needs a deployed re-smoke (otter
  re-introduces itself as the PA), not just green units.
- **033 / 034 role-file proximity.** 033 edits prompt assembly + `role-maestro.md`;
  034 edits skill curation + `role-lead.md`. Overlap is minimal, but if both
  touch role files, rebase the later PR.
- **032 is the clean independent lane** — no collision with Track 2; grab any
  time.

  debug/log, validated by **live-testing a real project**. Scoped from the S7
  research, numbers assigned at S8 planning:
  - **W1** responsive/touch shell — iPad portrait + landscape; fix the 900px
    chat-rail-hide (the rail vanishes at iPad-portrait width today).
  - **W2** PWA install — web app manifest + service worker + apple-touch-icon /
    apple-mobile-web-app meta + offline shell.
  - **W3** decision-UI parity — 029 on the web: `/api/decision` endpoint +
    durable store + SSE decision bubble + reply field; multi-choice gate support.
  - **W4** Web Push (iOS/iPadOS 16.4+) — VAPID + service-worker push; retires
    Telegram's alert role. Follow-on after W1–W3.
- **`research-consolidate`** (the stray 4th pattern) — optional, S8+.
- Mid-run Workflow **steering** (runs stay read-only, ADR 0014).
- Non-Claude leaf models (needs the Phase 5 adapter layer).
- Centralising every scattered PA reference (033 is identity-in-prompt only).
