# Questions

Things to answer before designing.

- Is `PROJECT_PLAN.md` the actual problem, or is the issue broader?
- What docs exist today and what is each one's current state?
- What is the minimum-viable set of files / directories?
- How does the ticket workflow interact with reference docs that span
  multiple Tickets?
- What's the "trivial threshold" — when can a Ticket skip the
  workflow?
- What happens to 31 past sprints — backfill into the new structure,
  or summarise into a `CHANGELOG.md`?
- Where does the working-method text live — `CLAUDE.md`, a separate
  `CONVENTIONS.md`, or somewhere in `docs/`?
- Where do reference docs (`CONTEXT`, `README`, `DEPLOYMENT`,
  `ARCHITECTURE`) fit if not in the three altitudes?
- Do the existing root-level docs (`STATUS.md`, `ROADMAP.md`) survive
  the restructure, or get absorbed?
- Does this work fit before, alongside, or after the Phase 1 runtime
  migration?
