# Sprint 2026-Q2-S10

**Status:** Active
**Window:** 2026-06-30 → 2026-07-28
**Extended:** window pushed out two weeks (was 07-14) — the 051/052/053 UI
redesign is now produced in the external **Claude design app**, then a single new

**Goal:** Make the web genuinely usable as **the Delegator's Desk** — the
delegate-and-supervise surface for autonomous loops (roadmap Phase 5,
[ADR 0027](../adr/0027-web-delegators-desk.md)). Today the web is a good monitor
and approver but a poor control panel: ~30 of ~35 capabilities are command-only
and the home page is unusable. S10 rebuilds the home from first principles — a
**Stack home** (needs-you lane as hero + project glance + delegate bar + quota
chip) that opens into a **tabbed Work view** (2–3 maestro conversations, active
tab = default target, clear/history) — on a **trimmed command set**, and cleans
up after. The three redesign tickets (051/052/053) are **designed in the Claude
design app** — their deliverable is an approved mockup, not shipped code — and a
single new Claude Code ticket
([`065`](../tickets/065-implement-desk-redesign/)) implements those mockups into
`src/hive/web` and wires the backend behind them. This is the FE-weighted half of
the FE+BE cadence; the dogfood + isolation + harnesses that *fill* the desk are
future work (roadmap Phase 6/7, stubbed as backlog tickets 055–063 — re-grilled
into a sprint after S10).

> **Why now.** Phase 4 shipped the web *surface* (PWA + Web Push, verified on the
> iPad). A first-principles brainstorm chose the **Delegator's Desk** mental model
> (delegate + supervise autonomous loops, not pilot a cockpit) and a home layout
> ("Stack" → tabbed "Work"). The redesign mostly re-surfaces existing capability;
> the one new binding (project ↔ home/loop status) is also what the dogfood
> needs later. The visual/UX design is produced in the **Claude design app**
> (tickets 051/052/053, deliverable = approved mockups); a single Claude Code
> ticket ([`065`](../tickets/065-implement-desk-redesign/)) then implements and
> wires it.

## Risks

- **One large implementation ticket (065).** The full home + tabbed Work view now
  ship in a single Claude Code ticket instead of two. Splitting the *design* out
  to the Claude design app shrinks the code surface, but 065 is still the heaviest
  ticket — it may spill past the window.
- **Design-app detour — external + un-timeboxed.** 051/052/053 are designed in the
  Claude design app, outside Claude Code and off this repo's CI/velocity signals.
  The design round-trip has no fixed schedule and gates 065, so it is the main
  risk to the extended window; 065 cannot start until the designs are approved.
- **051 blast radius.** Folding four approval/decision surfaces into one (built in
  065) touches the mode/vault/gate/decision paths — keep the full web + approval
  test suite green and re-smoke each interrupt type.
- **On-device re-smoke.** 065 changes live web behaviour → it needs a deployed
  re-smoke on an **actual iPad** (installed PWA), not just green units.
- **Shared web-file rebasing** — 065 lands all the redesign changes in
  `src/hive/web` in one place, so cross-ticket rebasing largely goes away; watch
  only for overlap with 054.
