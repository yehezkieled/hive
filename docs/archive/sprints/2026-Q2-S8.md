# Sprint 2026-Q2-S8

**Status:** ✅ Closed 2026-06-25 — goal met (interaction layer shipped; 041 Web Push spills → S9 as designed). Frozen.
**Window:** 2026-06-21 → 2026-07-05
**Goal:** Make the **web the primary control surface** for Hive from an iPad —
the "daily driver" of Phase 4. Today the web is already a working command +
approval surface (chat → `/api/command`, ~35 commands, mode/vault/gate approvals,
SSE, React dashboard), but it is unusable on touch (the chat rail vanishes at
iPad-portrait width; Enter doesn't send) and missing the pieces that let you act
on-device and be pinged when away. S8 ships the **interaction** layer: a
responsive touch shell, decision answers on the web (029 → web), an
"awaiting-you" attention router, and an installable PWA. **Web Push** — the
feature that finally demotes Telegram to debug/log — is the designated spill to
**S9**, since it is large and gated by the PWA. This is an interaction sprint, not
an observability one: the dashboard already out-ranks peer harnesses, so S8 adds
**zero new widgets**.

`pytest -m "not integration"` green.

> **Why now / research note.** A web-surface survey + a competitor scan (Claude
> Code Remote Control, Codex, Devin, Cursor, OSS orchestrators) found Hive
> already owns the hard half — the architecture (VPS-executes / thin-window) and
> the human-in-the-loop machinery (gate bridge 003, phase-confirm 019, the 029
> decision channel). The S8 gaps are almost entirely **delivery-layer**: touch
> shell, decision-UI parity, attention routing, PWA install, and (S9) Web Push.

## Dependencies

What must land before what. Independent tickets stand alone — grab any time.

```
  037 touch shell    — independent · do FIRST (device unusable on touch without it)
  038 decision UI    — independent
  039 awaiting badge — independent
  040 PWA install ──▶ 041 web push   (⚠ 041 spills → S9; large + gated)

  ⚠ 037–040 all edit src/hive/web (templates/static) → not logical blockers, but
    rebase the later PR; the fleet merges one at a time.
```

Suggested start order (a topo read, not a fixed schedule):

1. **037 first** — unblocks the device; everything else is judged on it.
2. **038 / 039 any time, in parallel** — independent interaction wins.
3. **040** — install; then **041 web push** rides on it (spills → S9).

## Risks

- **037 is the gate.** If the touch shell slips, the whole "daily driver" goal
  slips — nothing else is verifiable on the iPad without it. Mitigated: the
  worst bug (Enter-to-send) is already hotfixed (PR #198).
- **Behaviour-change re-smokes.** 037/038/039 change live web behaviour → each
  needs a deployed re-smoke on an actual iPad (Safari downloads/compiles/mounts;
  a curl-200 is not sufficient), not just green units.
- **Shared-file rebasing.** 037–040 all touch `src/hive/web`; land order matters,
  later PR rebases.
- **041 scope creep.** Web Push (VAPID + SW + store + delivery) is genuinely
  large and iOS-16.4+-finicky; committing it to S8 behind four others is how the
  sprint misses. Held as S9-first / stretch on purpose.

## Out of scope

- **Web Push in S8** (041) — spill → S9 (pull in first), or stretch only.
- **New observability widgets** — the dashboard already leads peers; S8 is
  interaction, not charts.
- **Inline diff-review / approve-merge from the phone** — high-value but Phase-4+
  (collides with Hive's deliberately finicky worktree/branch conventions).
- **Mid-run Workflow steering** — runs stay read-only (ADR 0014).
- **The 6-pattern interaction-skill library** (debate/blackboard/tournament/…) —
  S9 backend track (ships as global skills with a thin JD awareness pointer; a
  new ADR will amend 0021). Pairs with S9's web work under the FE+BE-combined
  sprint shape.

## Note — sprint shape going forward

From **S9**, sprints combine a **web/front-end track** with a **backend/logic +
bug-fix track** (per the developer's direction), rather than running an all-web
or all-backend sprint. S8 stays web-weighted because its job is unblocking the
iPad — but it is not pure front-end (038's `/api/decision` + 039's `view_model`
work are backend). The S9 backend track's first candidate is the **6-pattern
interaction-skill library** (loop-engineering infrastructure: the autonomous loop
self-organizes its fan-outs without the human dictating).
