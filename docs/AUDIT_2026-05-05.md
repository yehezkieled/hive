### Gate 3 — Concurrency lock (2026-05-05) — commit `955b660`

**Single high-risk commit, 1 file, +38/−13 lines, full suite 677 passed.**

| Audit ID | File | Change |
|---|---|---|
| C3 | `src/hive/process/manager.py` | Added `ProcessManager._state_lock = asyncio.Lock()`. Wrapped every mutation of `_entities` / `_sessions` with `async with self._state_lock:` — `register_maestro`, `register_entity`, `spawn_entity` (paired entity+session insert), `create_team`, `spawn_worker`, `kill_entity` (separate `_sessions.pop` and `_entities.pop` with `worktree.remove` between them), `stop_all`, `compact_entity`. Read protection: `health_check` and `get_status` snapshot `list(_entities.items())` to avoid `dictionary-changed-size` during awaits. |

**Deadlock avoidance:** every locked block contains only the dict op — no `await` inside. `send_to_entity`, `_handle_actions`, and Sprint 23 `_peer_directory_for` stay UNLOCKED so they can safely call back into manager methods that re-acquire the lock. `asyncio.Lock` is not re-entrant; nesting would deadlock the peer-routing path.

**Sites deliberately not locked:** single-key `_entities.get(...)` reads (atomic under the GIL); `_handle_actions` body (calls multiple lock-acquiring methods); Sprint 23 peer-routing reads in `_peer_directory_for` (sync method, single-key reads, called from inside `send_to_entity`).

**Test results:** ruff clean; full pytest suite **677 passed in 161s**; integration suite passes on retry (one flake in live-Claude tests unrelated to lock changes).
